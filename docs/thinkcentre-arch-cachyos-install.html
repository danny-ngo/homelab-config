Arch + CachyOS installation guide

A destructive, start-to-finish build for an always-on headless development node: minimal Arch Linux, full CachyOS optimized repositories, the default CachyOS kernel, an independent Arch LTS fallback, Tailscale access, bounded Docker, and the repository’s execution-node automation.

01 · Target design

Know what this procedure builds

This is intentionally a single-purpose machine. It does not install a graphical desktop, K3s, databases, public ingress, or irreplaceable state.

Firmware
UEFI, Secure Boot disabled, firmware Fast Boot disabled if it hides the boot menu.
Storage
One whole NVMe/SATA disk: 1 GiB FAT32 EFI System Partition and an ext4 root filesystem.
Networking
The USB Wi-Fi adapter provides Internet during installation and remains a fallback after boot. systemd-networkd supplies DHCP for both Wi-Fi and Ethernet, with wired preferred when both are connected; Tailscale provides remote access.
Boot
systemd-boot with a five-second menu; linux-cachyos is primary and official linux-lts remains independently bootable.
Workload
Bare-metal T3 Code, Codex CLI, Git, builds/tests, Docker/Compose, language toolchains, isolated workspaces and bounded caches. GitHub holds durable project source.
State
Configuration in Git/Ansible; source repositories and selected caches are rebuildable. No unique service state belongs here.
This procedure erases the selected disk. Read the model and size from lsblk immediately before partitioning. Disconnect any disk you cannot afford to erase.

02 · Prepare

Collect facts and recovery material

  1. Record the hardware

    Write down the exact ThinkCentre model, CPU, RAM, disk, Ethernet controller, USB Wi-Fi chipset, firmware version and Lenovo serial number. Photograph the current firmware settings. Confirm the current Arch ISO detects the USB adapter before relying on it as the only setup connection.

  2. Set the firmware

    • Boot mode: UEFI only; disable CSM/Legacy Boot.
    • Secure Boot: disabled, per this design.
    • Virtualization: enable Intel VT-x/VT-d or the AMD equivalents.
    • USB boot: enabled. Disable Fast Boot if USB input is skipped during startup.
    • Power: choose “Power on after AC loss” if this node should recover automatically after an outage.

  3. Create and verify an Arch installation USB

    Download the current ISO, signature and checksum from the official Arch download page. Verify the signature before writing the ISO. Keep this USB as the recovery medium after installation.

  4. Reserve the network identity

    Plan hostname thinkcentre. After the first boot, reserve the wired NIC’s MAC address in the router instead of hard-coding a static address on the host. The USB Wi-Fi lease can be used during setup; reserve its MAC too only if Wi-Fi will remain a regular access path.

Required at the machine

Monitor, keyboard, Arch USB, the known-working USB Wi-Fi adapter and Wi-Fi credentials. An Ethernet cable is optional during setup but recommended for the node’s steady-state connection. Keep access to the router’s DHCP leases.

Values used below

Disk /dev/nvme0n1, ESP p1, root p2, hostname thinkcentre, user homelab. Substitute carefully.

03 · Live environment

Boot the Arch ISO and prove the basics

  1. Confirm UEFI mode

    ls /sys/firmware/efi/efivars

    A populated directory is the expected result. Reboot and correct the firmware mode if it does not exist.

  2. Connect the USB Wi-Fi adapter and confirm Internet access

    lsusb
ip link
rfkill
rfkill unblock wifi
iwctl device list
iwctl station WIFI_DEVICE scan
iwctl station WIFI_DEVICE get-networks
iwctl station WIFI_DEVICE connect "WIFI_SSID"

timedatectl set-ntp true
ip address
ip route
ping -c 3 archlinux.org

    Replace WIFI_DEVICE with the name shown by iwctl device list; it is commonly wlan0. The connect command prompts for the passphrase, avoiding credentials in shell history. The Arch ISO already runs iwd, systemd-networkd and systemd-resolved. If the adapter does not appear in both lsusb and ip link, stop and resolve its driver or firmware support before erasing the disk.

  3. Identify the installation disk

    lsblk -e7 -o NAME,SIZE,MODEL,SERIAL,TYPE,FSTYPE,MOUNTPOINTS
fdisk -l

    For a SATA SSD, subsequent partition names will look like /dev/sda1 and /dev/sda2, not NVMe’s p1/p2.

04 · Disk

Partition, format and mount

The layout favours transparent recovery over snapshot features. ext4 is sufficient because the node is rebuilt from code and keeps no unique service state.

Final destructive checkpoint. The commands below irreversibly target /dev/nvme0n1.

  1. Create a fresh GPT and two partitions

    sgdisk --zap-all /dev/nvme0n1
sgdisk --new=1:0:+1GiB --typecode=1:ef00 --change-name=1:EFI /dev/nvme0n1
sgdisk --new=2:0:0 --typecode=2:8304 --change-name=2:ARCHROOT /dev/nvme0n1
partprobe /dev/nvme0n1
lsblk -f /dev/nvme0n1

  2. Format the filesystems

    mkfs.fat -F 32 -n EFI /dev/nvme0n1p1
mkfs.ext4 -L ARCHROOT /dev/nvme0n1p2

  3. Mount root and the EFI System Partition

    mount /dev/nvme0n1p2 /mnt
mount --mkdir /dev/nvme0n1p1 /mnt/boot
findmnt /mnt
findmnt /mnt/boot

05 · Base system

Install only what is needed to boot and recover

  1. Optionally choose nearby mirrors

    reflector --country Canada,United States \
  --latest 20 --protocol https --sort rate \
  --save /etc/pacman.d/mirrorlist

    If Reflector cannot produce a usable list, retain the ISO’s generated mirror list.

  2. Install the bootstrap system

    pacstrap -K /mnt \
  base base-devel linux-lts linux-firmware intel-ucode \
  git openssh sudo vim curl ca-certificates iwd

    For an AMD ThinkCentre, replace intel-ucode with amd-ucode. The CachyOS package layer is added only after a known-good Arch LTS boot.

  3. Generate mounts and preserve the live Wi-Fi profile

    genfstab -U /mnt >> /mnt/etc/fstab
cat /mnt/etc/fstab

install -d -m 0700 /mnt/var/lib/iwd
cp -a /var/lib/iwd/. /mnt/var/lib/iwd/
find /mnt/var/lib/iwd -type f -exec chmod 600 {} +

arch-chroot /mnt

    Do not continue if root and /boot are absent or mapped to the wrong UUIDs. The copied iwd profile lets the installed system reconnect to the same Wi-Fi network on first boot; it contains authentication material, so keep it root-only and never commit it to Git. If you deliberately installed over Ethernet, the empty copy is harmless.

06 · Arch configuration

Set identity, locale, user and dual-path networking

  1. Set Toronto time and the hardware clock

    ln -sf /usr/share/zoneinfo/America/Toronto /etc/localtime
hwclock --systohc

  2. Generate the locale

    sed -i 's/^#en_CA.UTF-8 UTF-8/en_CA.UTF-8 UTF-8/' /etc/locale.gen
sed -i 's/^#en_US.UTF-8 UTF-8/en_US.UTF-8 UTF-8/' /etc/locale.gen
locale-gen
printf 'LANG=en_CA.UTF-8\n' > /etc/locale.conf

  3. Set the hostname and local hosts file

    printf 'thinkcentre\n' > /etc/hostname
printf '127.0.0.1 localhost\n::1 localhost\n127.0.1.1 thinkcentre\n' > /etc/hosts

  4. Create the administrator

    passwd
useradd --create-home --groups wheel --shell /bin/bash homelab
passwd homelab
install -m 0440 /dev/null /etc/sudoers.d/10-wheel
printf '%%wheel ALL=(ALL:ALL) ALL\n' > /etc/sudoers.d/10-wheel
visudo -cf /etc/sudoers.d/10-wheel

  5. Configure DHCP for wired and USB Wi-Fi

    install -d /etc/systemd/network
cat > /etc/systemd/network/20-wired.network <<'EOF'
[Match]
Name=en*

[Link]
RequiredForOnline=routable

[Network]
DHCP=yes

[DHCPv4]
RouteMetric=100

[IPv6AcceptRA]
RouteMetric=100
EOF

cat > /etc/systemd/network/30-wireless.network <<'EOF'
[Match]
Name=wl*

[Link]
RequiredForOnline=routable

[Network]
DHCP=yes
IgnoreCarrierLoss=3s

[DHCPv4]
RouteMetric=600

[IPv6AcceptRA]
RouteMetric=600
EOF

install -d /etc/systemd/system/systemd-networkd-wait-online.service.d
cat > /etc/systemd/system/systemd-networkd-wait-online.service.d/10-any-interface.conf <<'EOF'
[Service]
ExecStart=
ExecStart=/usr/lib/systemd/systemd-networkd-wait-online --any
EOF

systemctl enable systemd-networkd.service
systemctl enable systemd-resolved.service
systemctl enable systemd-timesyncd.service
systemctl enable iwd.service
systemctl enable sshd.service

    iwd authenticates the wireless link; systemd-networkd remains the only DHCP client. The lower route metric makes Ethernet preferred when it is connected, while --any allows boot to reach network-online through either interface.

Do not enable another DHCP manager. NetworkManager, dhcpcd and iwd’s built-in network configuration must not compete with systemd-networkd. Leave EnableNetworkConfiguration unset or false in /etc/iwd/main.conf.

07 · Boot

Install systemd-boot with LTS as the initial default

  1. Install the boot manager

    bootctl --esp-path=/boot install
install -d /boot/loader/entries

  2. Create the loader configuration

    cat > /boot/loader/loader.conf <<'EOF'
default arch-lts.conf
timeout 5
console-mode auto
editor yes
EOF

  3. Create the LTS entry

    ROOT_UUID=$(blkid -s UUID -o value /dev/nvme0n1p2)
cat > /boot/loader/entries/arch-lts.conf <<EOF
title   Arch Linux (LTS fallback)
linux   /vmlinuz-linux-lts
initrd  /intel-ucode.img
initrd  /initramfs-linux-lts.img
options root=UUID=${ROOT_UUID} rw
EOF

bootctl

    Use /amd-ucode.img on AMD. Correct any parse or missing-file errors before leaving the chroot.

  4. Finish the live-ISO phase

    exit
ln -sf ../run/systemd/resolve/stub-resolv.conf /mnt/etc/resolv.conf
umount -R /mnt
reboot

    Remove the USB when firmware restarts. The machine should show a five-second menu and boot the LTS kernel.

08 · First boot

Prove stock Arch before adding optimizations

Log in locally as homelab. Every check here should pass before CachyOS packages are introduced.

uname -r
findmnt / /boot
networkctl status
resolvectl status
iwctl device list
iwctl station WIFI_DEVICE show
ping -c 3 archlinux.org
systemctl --failed
sudo journalctl -b -p err
bootctl list
sudo pacman -Syu
Baseline gate. Continue only when the current kernel name contains lts, networking and DNS work, /boot is mounted, and no unexplained failed units remain.

09 · CachyOS package layer

Add the optimized repositories and primary kernel

  1. Verify the CPU tier

    /lib/ld-linux-x86-64.so.2 --help | grep supported
lscpu | sed -n '1,24p'

    Use x86-64-v3 when reported. Treat Intel 12th-generation and newer hybrid CPUs as v3 unless AVX-512 is genuinely usable across all enabled cores. Never choose v4 by model year alone.

  2. Download, inspect and run the official repository helper

    mkdir -p ~/setup
cd ~/setup
curl -O https://mirror.cachyos.org/cachyos-repo.tar.xz
tar -xf cachyos-repo.tar.xz
cd cachyos-repo
less cachyos-repo.sh
sudo ./cachyos-repo.sh

    Confirm the helper selected the expected CPU tier and backed up /etc/pacman.conf.

  3. Review repository priority

    grep -nE '^\[[^]]+\]|^Include' /etc/pacman.conf
pacman-conf --repo-list

    The selected CachyOS architecture repositories and [cachyos] should appear above Arch [core] and [extra].

  4. Update and reinstall native packages from the preferred repositories

    sudo pacman -Syu
pacman -Qqn | sudo pacman -S -

    The second command intentionally revisits every repository package, selecting the highest-priority provider. Review the transaction before confirming. This is the point at which the base gains CachyOS optimized replacements.

  5. Install the primary kernel

    sudo pacman -S linux-cachyos
ls -lh /boot/vmlinuz-* /boot/initramfs-*

    Add linux-cachyos-headers only when a DKMS or kernel-module build actually requires them.

  6. Add the CachyOS boot entry and make it the default

    ROOT_UUID=$(findmnt -no UUID /)
sudo tee /boot/loader/entries/arch-cachyos.conf >/dev/null <<EOF
title   Arch Linux (CachyOS kernel)
linux   /vmlinuz-linux-cachyos
initrd  /intel-ucode.img
initrd  /initramfs-linux-cachyos.img
options root=UUID=${ROOT_UUID} rw
EOF

sudo bootctl set-default arch-cachyos.conf
bootctl list
sudo systemctl reboot
Fallback stays independent. Do not replace linux-lts with linux-cachyos-lts. The purpose of this entry is recovery from both a CachyOS patch regression and a CachyOS repository problem.

10 · Execution node

Apply the repository-managed development profile

The homelab repository owns mise with Node.js 24, Go, Rust and Herdr; Codex CLI and OpenCode; Docker settings; Tailscale; the T3 Code headless server; and dotfiles integration. Avoid maintaining a second manual configuration in parallel.

  1. Install the bootstrap prerequisites

    Only Git and OpenSSH are required before cloning. The managed-node bootstrap installs the global uv package, a per-user uv-managed Python 3.14, and the user's global 3.14 pin. It does not install Ansible.

    sudo pacman -S --needed git openssh

  2. Clone this configuration repository

    mkdir -p ~/src
git clone YOUR_HOMELAB_CONFIG_REPOSITORY ~/src/homelab-config
cd ~/src/homelab-config

  3. Prepare the Arch managed node

    Run the prerequisite-only path on the ThinkCentre. It stops after uv, Python 3.14, and the global pin are ready. Production inventory and Vault remain on the MacBook controller.

    ./bootstrap.sh --prepare-only
uv python pin --global

  4. Check, apply and validate the execution-node playbook

    Return to the MacBook checkout. The controller playbook installs Tailscale, mise-managed Node.js 24, Go, Rust and Herdr, Codex CLI, OpenCode, and a systemd-managed T3 Code headless server exposed with Tailscale Serve.

    ./bootstrap.sh --profile execution-node --limit thinkcentre --check
./bootstrap.sh --profile execution-node --limit thinkcentre
make validate LIMIT=thinkcentre

    Use the repository’s current documented targets if they change. Do not bypass a failing check-mode run without understanding the difference.

Keep one package owner. If the execution-node role is unavailable, repair or check out this repository from the MacBook controller. Do not maintain a parallel manual package list on the node.

11 · Remote access

Establish SSH and Tailscale without locking out recovery

  1. Install a public SSH key

    From the MacBook, after verifying the router lease and host identity. THINKCENTRE_LAN_IP may initially be the USB Wi-Fi address; switch the router reservation and your normal access path to the wired address once Ethernet is connected.

    ssh-copy-id homelab@THINKCENTRE_LAN_IP
ssh homelab@THINKCENTRE_LAN_IP

  2. Verify the host key out of band

    sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

    Compare the locally displayed fingerprint with the MacBook’s first-use prompt before accepting it.

  3. Enroll Tailscale without taking over DNS

    sudo systemctl enable --now tailscaled
sudo tailscale up --accept-dns=false
tailscale status
tailscale ip -4

    If tailnet ACLs use tags, enroll using the approved reusable/pre-authorized auth key managed through Vault rather than pasting it into shell history.

  4. Test both paths before hardening SSH

    ssh homelab@THINKCENTRE_LAN_IP
ssh homelab@THINKCENTRE_TAILSCALE_IP

    Keep the local console logged in during testing. Disable SSH passwords only after key login, Tailscale login and console recovery have all been proven.

12 · Resource bounds

Protect a small chassis from unbounded development workloads

  1. Bound Docker logs and preserve running containers across daemon upgrades

    sudo install -d /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "live-restore": true,
  "log-driver": "json-file",
  "log-opts": {
    "max-file": "3",
    "max-size": "10m"
  }
}
EOF
sudo dockerd --validate --config-file=/etc/docker/daemon.json
sudo systemctl enable --now docker
sudo systemctl restart docker

  2. Add compressed swap as an OOM safety valve

    sudo pacman -S zram-generator
sudo tee /etc/systemd/zram-generator.conf >/dev/null <<'EOF'
[zram0]
zram-size = min(ram / 2, 4096)
compression-algorithm = zstd
EOF
sudo systemctl daemon-reload
sudo systemctl start systemd-zram-setup@zram0.service
swapon --show
zramctl

    This caps the virtual zram device at 4 GiB. It is protection against short spikes, not permission to oversubscribe memory indefinitely.

  3. Bound persistent logs

    sudo install -d /etc/systemd/journald.conf.d
sudo tee /etc/systemd/journald.conf.d/10-size-limits.conf >/dev/null <<'EOF'
[Journal]
SystemMaxUse=500M
RuntimeMaxUse=100M
MaxRetentionSec=14day
EOF
sudo systemctl restart systemd-journald

  4. Enable storage maintenance and hardware visibility

    sudo pacman -S smartmontools lm_sensors pacman-contrib
sudo systemctl enable --now smartd.service
sudo systemctl enable --now fstrim.timer
sudo systemctl enable --now paccache.timer
sudo sensors-detect --auto
sensors
sudo smartctl -a /dev/nvme0n1
Docker group membership is root-equivalent. Rootful Docker and this access are accepted for the declared execution-node account. Treat that account and every agent running as it as trusted host administration.

13 · Acceptance

Validate, document and hand off

Run the final smoke test

uname -r
pacman-conf --repo-list
bootctl list
systemctl --failed
journalctl -b -p err
networkctl status
resolvectl status
iwctl device list
iwctl station WIFI_DEVICE show
tailscale status
ssh -V
docker version
docker run --rm hello-world
swapon --show
df -h /
df -h /boot
sensors
sudo smartctl -H /dev/nvme0n1

Prove the fallback before declaring success

sudo systemctl reboot --boot-loader-entry=arch-lts.conf

After the LTS boot, confirm network, SSH, Tailscale and Docker. Then return to the primary kernel without changing the persistent default:

sudo systemctl reboot --boot-loader-entry=arch-cachyos.conf
  • linux-cachyos boots automatically after five seconds.
  • linux-lts has been booted successfully at least once.
  • The USB Wi-Fi adapter reconnects after boot and wired Ethernet takes route priority when attached.
  • LAN and Tailscale SSH both work using a key.
  • The host fingerprint is recorded and verified.
  • Router DHCP reservation is set.
  • Ansible check and validation runs pass.
  • Docker logs, journald and package cache are bounded.
  • No unique state exists only on this node.
  • The Arch USB, monitor and keyboard remain available for recovery.
