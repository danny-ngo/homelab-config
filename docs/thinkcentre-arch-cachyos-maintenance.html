01 · Posture

Keep failure cheap and observable

The machine is an always-on remote development appliance, not a source-of-truth host. Its availability matters while work is running, but recovery should favour a clean boot or rebuild over heroic repair. Project source must be recoverable from GitHub; see the workspace durability policy.

Always true

  • Complete upgrades only: pacman -Syu.
  • CachyOS repositories remain above Arch repositories.
  • Primary and fallback kernels stay installed.
  • Configuration is committed before risky changes.
  • Reboots remain deliberate and observable.

Never normal

  • Running pacman -Sy package.
  • Enabling unattended or offline-update reboot timers.
  • Deleting the fallback kernel to save space.
  • Ignoring pacman, initramfs or DKMS errors.
  • Running cleanup with --volumes casually.
  • Keeping unique credentials or project state only here.
Severity model. A broken primary kernel is a low-severity incident when the LTS entry and local console work. A damaged boot filesystem or lost configuration is higher severity, which is why both are checked and backed up explicitly.

02 · Schedule

Use a small, repeatable maintenance rhythm

CadenceActionsEscalate when
Before workConfirm SSH/Tailscale, free space and no failed units if the node has been idle.The host rebooted unexpectedly, storage changed, or the previous session ended abnormally.
End of work sessionReview changes, run relevant tests, commit intentional project source and push the active branch to GitHub.The repository has no expected remote, the branch has no upstream, or unique work cannot be safely committed or backed up.
Every 1–2 weeksRead Arch news, inspect pending updates, run the controlled update workflow, reboot and smoke-test.Core packages, kernel, bootloader, microcode or filesystem tools report errors.
MonthlyReview Docker storage, package cache, orphans, journal size, exposed sockets, firewall posture, SMART, temperatures and configuration drift.Disk exceeds 80%, an unexpected service is listening, SMART is not healthy, or sustained load thermally throttles.
QuarterlyBoot LTS deliberately, boot the Arch USB, confirm backups can recreate inventory, and run an Ansible check.The fallback entry or recovery media does not work.
Before absenceLeave the host on a known-good kernel; avoid major upgrades immediately before travel.No trusted person can reach the physical console.

03 · Routine procedure

Perform a controlled full-system update

1

Preflight

Do boot-chain updates while at home. A normal userspace update can be done remotely, but do not schedule a reboot until physical recovery is practical.

date
uptime
uname -r
systemctl --failed
df -h / /boot
findmnt /boot
bootctl list
pacman-conf --repo-list
pacman -Si pacman | sed -n '1,10p'
pacman -Qi pacman | grep -E '^(Name|Version|Installed From)'
tailscale status
ss -lntup
docker ps --format 'table {{.Names}}\t{{.Status}}'
sudo journalctl -b -p err --no-pager
  • No unexplained failed units or listening services.
  • At least 5 GiB free on root and 250 MiB free on the ESP.
  • Both CachyOS and LTS boot entries are present.
  • CachyOS architecture repositories and [cachyos] precede Arch repositories; pacman’s origin is expected.
  • Important work is committed or backed up.
2

Review change sources

Read Arch Linux news and the linked CachyOS kernel, repository and post-install pages for notices relevant to this package layer. Preview repository updates without performing a partial upgrade:

checkupdates || true
pacman -Qu
pacman-conf --repo-list

checkupdates comes from pacman-contrib and uses a temporary database, preserving Arch’s full-upgrade rule.

3

Upgrade and read all output

sudo pacman -Syu

Stop before rebooting if pacman reports an initramfs generation error, bootloader error, file conflict, signature problem, DKMS failure or a .pacnew file for a configuration you depend on.

find /etc -xdev -type f \( -name '*.pacnew' -o -name '*.pacsave' \) -print
sudo tail -n 120 /var/log/pacman.log
sudo mkinitcpio -P
sudo bootctl update
bootctl

The explicit initramfs rebuild is a verification step. It must complete cleanly for both installed kernels.

Keep updates operator-controlled. CachyOS documents pacman-offline, Cachy-Update and an optional automatic reboot timer. They are intentionally not used on this remote execution node: the runbook requires reading news and transaction output, confirming both initramfs images, and choosing the reboot window.
4

Reboot deliberately

sudo systemctl reboot

If the host does not return within its normal boot time plus two minutes, stop retrying remotely and use the physical console.

5

Post-update smoke test

uname -r
systemctl --failed
journalctl -b -p err --no-pager
pacman -Qdtq
networkctl status
resolvectl status
tailscale status
docker version
docker run --rm hello-world
swapon --show
df -h / /boot
sensors
sudo smartctl -H /dev/nvme0n1
Close the maintenance window only when remote development works. Clone or open a repository, run a small build/test, and start a disposable container. A green boot alone is insufficient.

04 · Boot control

Manage primary, one-shot and fallback kernels

Persistent default
sudo bootctl set-default arch-cachyos.conf
Next boot only: LTS
sudo systemctl reboot --boot-loader-entry=arch-lts.conf
Next boot only: CachyOS
sudo systemctl reboot --boot-loader-entry=arch-cachyos.conf
List and parse
bootctl list and bootctl
Update loader binary
sudo bootctl update
Firmware setup
sudo systemctl reboot --firmware-setup

Quarterly fallback drill

  1. Commit or stop active work.
  2. One-shot boot arch-lts.conf.
  3. Verify LAN, Tailscale, SSH, Docker and storage.
  4. Inspect journalctl -b -p err.
  5. One-shot boot back to arch-cachyos.conf.
Do not confuse the fallback initramfs with the fallback kernel. initramfs-linux-cachyos-fallback.img contains broader module detection for the same CachyOS kernel. The independent recovery path is the separate linux-lts package and entry.

05 · Capacity

Keep caches, logs and heat bounded

Storage

df -h /
df -h /boot
sudo du -xhd1 /var | sort -h
du -xhd1 ~ | sort -h

Docker

docker system df -v
docker ps -a
docker image ls
docker volume ls

Thermals

sensors
sudo journalctl -k \
  --grep='thermal|thrott' \
  --no-pager

Safe cleanup order

# Review orphans; remove only packages whose purpose you understand.
pacman -Qdtq

# Keep three package versions; remove older cached packages.
sudo paccache -r

# Remove only stopped containers and images older than seven days.
docker container prune
docker image prune -a --filter 'until=168h'

# Keep two weeks of journal data within the configured size cap.
sudo journalctl --vacuum-time=14d

# Remove failed downloads and tool-specific caches only after review.
du -sh ~/.cache/* 2>/dev/null | sort -h
Never automate docker system prune --volumes. Volumes can contain databases, dependency caches or test fixtures whose value is not obvious from the name. Inspect them individually.

Monthly hardware check

sudo smartctl -a /dev/nvme0n1
sudo smartctl -t short /dev/nvme0n1
# After the device-reported wait time:
sudo smartctl -l selftest /dev/nvme0n1
systemctl status fstrim.timer smartd.service --no-pager

Audit optional CachyOS settings

pacman -Q cachyos-settings 2>/dev/null || true
pacman -Ql cachyos-settings 2>/dev/null | grep -E 'sysctl|udev' || true
sysctl kernel.sched_rt_runtime_us
cat /sys/block/nvme0n1/queue/scheduler

cachyos-settings is intentionally absent unless a measured need justifies its desktop-oriented tuning. If present, review changes after package upgrades. Override sysctls in a later-named file under /etc/sysctl.d/ and udev rules under /etc/udev/rules.d/; never edit package files under /usr/lib. Put every accepted override in Ansible.

06 · Rebuild data

Back up configuration, not machine identity by accident

The desired state lives in Git and encrypted Vault files. Backups should make reconstruction fast without copying transient containers, package caches or host secrets into the repository.

Capture a rebuild manifest

mkdir -p ~/rebuild-manifest
pacman -Qqen > ~/rebuild-manifest/repo-packages.txt
pacman -Qqem > ~/rebuild-manifest/foreign-packages.txt
systemctl list-unit-files --state=enabled > ~/rebuild-manifest/enabled-units.txt
bootctl list > ~/rebuild-manifest/boot-entries.txt
lsblk -f > ~/rebuild-manifest/filesystems.txt
tailscale status > ~/rebuild-manifest/tailscale-status.txt

Back up or reproduce

MaterialPolicy
Homelab configuration and dotfilesPush clean commits to their remotes. Keep encrypted Vault material backed up separately.
SSH authorized keys and host fingerprintsAuthorized public keys may be declarative. Protect host private keys if preserving host identity; otherwise expect and verify a new fingerprint after rebuild.
Codex/T3 credentialsDo not commit or casually copy token stores. Prefer a fresh device login after rebuild.
Project sourceCommit and push at meaningful checkpoints, before switching machines, before maintenance, and at session end. Back up work that cannot yet be committed. Do not rely on stashes or local Docker volumes as durable source control.
Pacman cache and Docker imagesRe-download. Retain only enough package cache for immediate rollback.

Incident A

CachyOS kernel does not boot or the host never returns

  1. Connect the monitor and keyboard. Power-cycle once.
  2. At the systemd-boot menu, select Arch Linux (LTS fallback).
  3. If the menu is hidden, hold or tap Space immediately after firmware initialization.
  4. After LTS boots, gather evidence before changing packages.
uname -r
sudo journalctl -b -1 -k --no-pager
sudo journalctl -b -1 -p err --no-pager
sudo tail -n 160 /var/log/pacman.log
bootctl list
ls -lh /boot/vmlinuz-* /boot/initramfs-*

Choose one recovery

Stay on LTS temporarily 
sudo bootctl set-default arch-lts.conf
sudo pacman -Syu

This is the lowest-risk response. Keep the failing CachyOS entry installed while checking for a fixed update.

Reinstall the current CachyOS kernel 
sudo pacman -S linux-cachyos
sudo mkinitcpio -P
bootctl
sudo systemctl reboot --boot-loader-entry=arch-cachyos.conf
Downgrade from the package cache 
ls -1t /var/cache/pacman/pkg/linux-cachyos-*.pkg.tar.zst
sudo pacman -U /var/cache/pacman/pkg/linux-cachyos-PREVIOUS.pkg.tar.zst
sudo mkinitcpio -P
sudo systemctl reboot --boot-loader-entry=arch-cachyos.conf

Use this only as a short bridge. Do not hold the kernel indefinitely; upgrade normally when the regression is fixed.

Incident B

LAN, DNS, Tailscale or SSH is unavailable

Use the local console. Diagnose from the lowest layer upward.

ip link
ip address
ip route
networkctl status
resolvectl status
rfkill
iwctl device list
iwctl station WIFI_DEVICE show
ping -c 3 YOUR_ROUTER_IP
ping -c 3 1.1.1.1
ping -c 3 archlinux.org
systemctl status iwd systemd-networkd systemd-resolved tailscaled sshd --no-pager
sudo sshd -t
sudo journalctl -b -u iwd -u systemd-networkd -u systemd-resolved -u tailscaled -u sshd --no-pager
SymptomLikely action
No wired addressCheck cable/link LEDs, router lease and /etc/systemd/network/20-wired.network. Ensure no second network manager owns the interface.
USB Wi-Fi is absent or disconnectedCheck lsusb, rfkill, iwctl device list, the saved profile in /var/lib/iwd and /etc/systemd/network/30-wireless.network. Reconnect with iwctl station WIFI_DEVICE connect "WIFI_SSID"; do not enable iwd’s built-in DHCP.
IP works; names failVerify /etc/resolv.conf links to ../run/systemd/resolve/stub-resolv.conf, then restart resolved.
LAN works; Tailscale failsInspect tailscale status and service logs; reauthenticate only if the node is actually logged out.
Ping works; SSH failsRun sshd -t, correct the config, then restart sshd. Do not delete host keys.

Incident C

Root or the EFI System Partition is full

  1. Stop active builds and package operations.
  2. Identify the owner; do not delete random files from /var or /boot.
df -h / /boot
sudo du -xhd1 /var | sort -h
sudo du -xhd1 /var/lib | sort -h
du -xhd1 ~ | sort -h
docker system df -v
sudo journalctl --disk-usage
ls -lh /boot

Recover space in this order

sudo paccache -r
docker container prune
docker image prune -a --filter 'until=168h'
sudo journalctl --vacuum-size=400M

If /boot is full, confirm which kernel packages own each file with pacman -Qo. Remove only an intentionally retired kernel package through pacman—never delete its image manually.

Incident D

Pacman was interrupted, locked or reports inconsistent files

Do not reboot during an incomplete kernel, systemd, glibc or pacman transaction. Repair the package state first.

Confirm no package manager is still running

ps aux | grep -E '[p]acman|[m]akepkg'
sudo lsof /var/lib/pacman/db.lck 2>/dev/null

Only if no package process owns the lock:

sudo rm /var/lib/pacman/db.lck
sudo pacman -Syu
sudo pacman -Qk
sudo mkinitcpio -P
sudo bootctl update

Signature or keyring errors

sudo pacman -Sy --needed archlinux-keyring cachyos-keyring
sudo pacman -Su

This sequence immediately completes the full upgrade after refreshing the databases. Do not insert unrelated package installations between the two commands.

Incident E

Disable or fully remove the CachyOS package layer

Prefer booting LTS and waiting for a mirror or packaging fix. Perform a full repository rollback only when the CachyOS layer itself is the confirmed cause or you intentionally return to stock Arch.

Use the official removal helper

mkdir -p ~/setup/cachyos-remove
cd ~/setup/cachyos-remove
curl -O https://mirror.cachyos.org/cachyos-repo.tar.xz
tar -xf cachyos-repo.tar.xz
cd cachyos-repo
sudo ./cachyos-repo.sh --remove
sudo pacman -S core/pacman

Verify the result

pacman-conf --repo-list
pacman -Si pacman | sed -n '1,10p'
pacman -Qqn | sudo pacman -S -
sudo pacman -Syu
sudo mkinitcpio -P

The pacman reinstall must report Arch core as its repository. The full reinstall pass then selects stock Arch providers for every available repository package. Foreign/AUR packages remain separate and may need rebuilding. If a manual rollback leaves %INSTALLED_DB% warnings, follow the CachyOS optimized-repositories removal section rather than deleting package metadata ad hoc.

Keep linux-lts throughout the rollback. Remove linux-cachyos only after the system boots normally from Arch repositories and the LTS entry has been retested.

Incident F

Neither installed entry reaches a usable console

  1. Boot the verified Arch USB in UEFI mode.
  2. Establish Internet over Ethernet or the known-working USB Wi-Fi adapter, then identify the disk.
  3. Mount root and the ESP, then enter the installation.
rfkill unblock wifi
iwctl device list
iwctl station WIFI_DEVICE connect "WIFI_SSID"
ping -c 3 archlinux.org

lsblk -f
mount /dev/nvme0n1p2 /mnt
mount /dev/nvme0n1p1 /mnt/boot
arch-chroot /mnt

findmnt / /boot
pacman -Syu linux-lts linux-firmware iwd intel-ucode
mkinitcpio -P
bootctl --esp-path=/boot install
bootctl
exit
umount -R /mnt
reboot

For AMD, install amd-ucode. If networking in the installed system was the original problem, LTS may boot locally even before it is repaired.

Recreate the LTS loader entry if it is missing 
ROOT_UUID=$(blkid -s UUID -o value /dev/nvme0n1p2)
cat > /boot/loader/entries/arch-lts.conf <<EOF
title   Arch Linux (LTS fallback)
linux   /vmlinuz-linux-lts
initrd  /intel-ucode.img
initrd  /initramfs-linux-lts.img
options root=UUID=${ROOT_UUID} rw
EOF
bootctl

07 · Terminal recovery

Know when repair has become less reliable than rebuild

Reinstall instead of continuing forensic repair when any of these are true:

  • Filesystem or NVMe health is suspect.
  • Package ownership is broadly inconsistent.
  • Unknown manual changes make the system non-reproducible.
  • Recovery would take longer than the installation guide plus project re-cloning.
  • The node may have executed hostile code with host-level Docker access.

Rebuild order

  1. Preserve committed project work and the rebuild manifest.
  2. Record the current host SSH fingerprint so its replacement is expected.
  3. Re-run the companion installation guide.
  4. Apply the execution-node Ansible profile.
  5. Re-enroll Tailscale and Codex through their supported login flows.
  6. Restore repositories and only the selected caches worth keeping.
  7. Run the full acceptance checklist before deleting the old disk or backup.
