Acceptance gates

Protocol checks, idempotency, reboot persistence, and restore tests define success—not merely installed packages.

Primary computers

  • MacBook reaches every managed node over LAN or Tailscale.
  • Each Linux node passes its prerequisite-only bootstrap.
  • ThinkCentre completes a remote clone/build/test workflow.
  • Dotfiles apply from a pinned external revision.

DNS and edge access

  • The dedicated Pi 2 passes direct LAN UDP and TCP queries.
  • Tailnet DNS stays disabled until listener, firewall, ACL, and mobile-data validation pass.
  • The Pi 2 fixed commands wake both wired targets directly.
  • The Pi 1 sentinel detects independent DNS and HTTP failures.

K3s baseline

  • ThinkPad and both Pi 3 workers return Ready after reboot.
  • Second provisioning run has no unexplained changes.
  • Smoke workload uses a verified multi-arch image.
  • Pi 2 remains absent until its dedicated Pi-hole workload is defined.

State and recovery

  • Databases and pipeline metadata use named persistent paths.
  • Backups restore into a clean location.
  • Health checks exercise the real service protocol.
  • Recovery instructions remain available when K3s is down.

Phase 0 decisions still required

Remaining hardware and network facts, the second DNS host and DNS policy, access and configuration promotion, stateful service durability, and observability remain open. The single canonical backlog is Open homelab decisions.
